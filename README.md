# 清课 3.2

一款无广告、无需应用账号、在本机保存数据的 Android 课程表。支持自定义正方教务网址、文字型 PDF 导入、年度循环作息、批量调休调课、独立考试、系统提醒，以及可选择开启的口令分享与课表跟随。3.2 改进重叠课程展示，增加官网、可直接打开 App 的分享消息，以及打开 App 时在本机识别分享链接的入口。

官网与下载：[qk.sagiri.org](https://qk.sagiri.org/) · 源码：[SAGIRIxr/qingke](https://github.com/SAGIRIxr/qingke) · 安装包：[GitHub Releases](https://github.com/SAGIRIxr/qingke/releases) · 本版发布页：[v3.2.0](https://github.com/SAGIRIxr/qingke/releases/tag/v3.2.0)。

## 安装与首次使用

在官网选择 GH-Proxy 下载或 GitHub 官方下载，也可从发布页的 Assets 下载 `qingke-3.2.0-release.apk`，安装后打开手机桌面的「清课」。GH-Proxy 是可选的第三方下载代理。正式包关闭 WebView 调试，最低支持 Android 8.0，建议使用已更新的 Android System WebView。

1. 到「设置」→「学期与校历」→「学期管理」，点学期旁的「编辑」，核对学年、学期、实际开学日期和总周数。开学可以是任意星期；教学周仍为周一至周日，首周开学前不排基础课程。默认日期用于初始化，不代表学校校历。
2. 到「设置」→「学期与校历」→「上课作息」，按学校通知填写各小节起止时间及每年生效月日。
3. 到「设置」→「课程与考试」→「导入课程」，先选择目标学期，再选择正方网页、PDF 或粘贴课表；也可通过课表顶部的「＋」手动添加课程或考试。
4. 核对名称、星期、节次、周次和教室，确认后保存。查看单双周及调课后的实际日期，确认学期设置正确。
5. 如需提醒，在「设置」→「提醒与显示」→「提醒与课程状态」主动开启，并检查系统权限。

官方安装包使用固定维护签名；从相同签名的旧版升级时直接覆盖安装，不要先卸载或清除数据，建议升级前先导出备份。首次读取第一版课表会迁移数据；旧作息的完整日期会转换为每年循环的月日，并保留升级前原始备份。同名安排逐条保留，不自动合并。3.2 延续原有本地数据存储；各功能的验证范围、真机记录与限制见 [TESTING.md](TESTING.md)。

## 设置与返回

设置按「课程与考试」「学期与校历」「提醒与显示」「分享与数据」「应用」分组。分享及跟随入口位于「分享与数据」→「分享与跟随」，文件导出、恢复和历史版本统一放在「备份与恢复」。

进入下一层页面后，可用左上角返回、手机系统返回或预览页的 Esc 逐层退回，保留上一层尚未提交的表单内容和滚动位置。右上角关闭按钮退出整组弹窗。草稿只服务于当前编辑流程，仍需点保存或确认才能写入课表，不会因返回而自动保存。

## 查看与编辑课程

- 课表顶部保留学期、周次及导航，支持一周／三天视图、跟手左右滑动和回到今天；纵向正常滚动，系统减少动态效果设置会关闭切页动画。长课程名可填写简称，点开课程显示完整名称。
- 左侧时间轴同时显示每小节的开始与结束时间。当前正在上课的课程卡片高亮，并显示「上课中／课间休息」和整堂课的授课进度；进度按实际授课时间计算，课间暂停，继续上课后再前进。
- 「今天」显示当天课程、地点、小节状态和课程进度；在上课或课间时显示距下一节点的剩余分钟数。界面进度与系统通知分别显示，不需要开启通知才能查看。
- 每门课程支持多个上课安排，每条分别设置星期、起止节次、周次、教师和教室。周次支持范围、离散周次及单双周，例如 `1-16周(单)` 或 `1,3,5,8`。
- 课程支持颜色、简称、备注、考核方式和课程性质。考核方式可选考试／考查，或填写自定义文字；性质可填写必修、选修、实验等。考核方式本身不会自动生成考试日期或考场。
- 点开课程可选择「调整本次」「编辑这条重复安排」或「编辑整门课程」。删除课程或重复安排会同步删除其关联的单次变更。
- 已存在单次变更时，修改基础星期或周次若使该变更失去对应课程，会阻止保存。先处理相关变更，再调整基础安排。
- 支持课程搜索、时间冲突提示及周末显示开关。允许保存明确确认的冲突安排，便于保留学校课表原貌并进一步核对。
- 同一天的重叠时段使用占满该日期列宽的组合卡，显示重叠数量；安排较多或空间不足时折叠展示。点组标题或「查看全部」可查看完整清单，每项标明课程名称、实际起止时间、教室及「原安排」「调入」「单次调整」「整日补课」或「独立考试」来源。所有安排继续保留，可从清单逐项进入详情处理。
- 时间冲突按实际起止时间判断，并包括独立考试。连续相交的一组中，不一定每两项都同时上课，完整清单会分别列出各项实际重叠的对象。
- 「我的学期」可创建、切换、编辑和删除学期。名称可以按学年与上下学期自动生成，也可自定义。每个学期独立保存课程、考试、作息与教学调整，系统提醒使用当前选中的学期。
- 删除任何学期前都需确认并保留恢复版本；最后一个学期也可删除，之后会建立空白的「新学期」。删除本地学期不会自动撤销已经上传的分享，需在分享管理中单独撤销。

## 独立考试安排

通过顶部「＋」或设置中的考试入口，填写考试名称、日期、开始与结束时间、考场和备注；可关联已有课程，也可独立创建。考试使用明确的时间，不依赖课程节次，修改夏冬作息或设置整日停补课不会移动考试。

考试显示在周课表日期下的考试区及「今天」列表，与课程和其他考试有时间重叠时会提示。考试提醒沿用当前学期的课前提醒和状态通知开关，显示考试名称、考场及距开考／结束的时间。课程的「考核方式：考试」是课程属性，需要另外录入实际考试安排。

## 夏季、冬季作息与课间

每套作息都有名称和**每年生效月日**，按月日循环切换。例如夏季 `05-01`、冬季 `10-01`，每年自动执行；年初沿用上一年最后生效的方案。可只使用一套默认作息，不需要每年重填日期。

同一视图跨越作息切换日时，左侧仍显示起止时间，并明确标注所采用的日期和作息方案：当前视图包含今天时以今天为准，否则采用视图首日。采用另一作息的课程卡片另列实际起止时间；点「查看各日作息」或打开课程详情可核对对应日期的时间。

每套作息支持 1–24 节，各小节起止时间独立填写，必须顺序排列且不重叠。至少保留一套方案，各方案需包含现有课程使用的节次。修改前会显示确认内容并保存恢复版本。

小节可归入上午、下午或晚上。「同组时间联动」会随一节的调整顺延本组后续小节，保留课间，不移动其他组；也可从另一方案复制一个时段，并设置整体提前或推迟的分钟数。增加／减少节次、修改分组和复制时段保留表单中其他未保存的内容。

同一课程的多个小节在周课表中合并展示，详情按小节列出时间；小节间的空隙视为休息，例如 `08:00–08:45`、休息 10 分钟、`08:55–09:40`。累计授课时间扣除休息。对实际连续上课的安排，可选择「连上，不设课间」，此时整段按连续授课计算。

## 节假日、补课与单次调整

到「设置」→「学期与校历」→「调休与调课」，或点课表下方「调休 / 调课」，直接在月历点选日期；可跨月多选，也可展开单日或连续范围选择。选好日期后再选「停课」「补星期几」或「补某天的课」，保存前逐日预览变化，不覆盖已有规则。

只改某一堂课时点「单次调课」：先选课程及具体哪一次实际安排，再指定目标日期、开始和结束节次、教室与教师，也可只取消这一次。列表包含整日补课或已调课后的实际安排；目标节次显示当天作息的对应时间，确认前检查时间冲突。也可从课程详情进入「调整本次」。

| 操作 | 结果 |
| --- | --- |
| 日期标记 | 显示假日、校庆或考试周等名称，不改变课程 |
| 整日停课 | 停止当天基础安排；明确移入当天的单次课程仍保留，并提示核对 |
| 整日补课 | 指定实际日期补另一个具体日期的课；目标日原有基础课程被替代，来源日期不再重复上课 |
| 单次取消 | 只取消原安排的这一次课 |
| 单次移动／修改 | 更改这一次的日期、节次、地点、教师或备注 |
| 撤销变更 | 移除指定规则，相关课程按剩余有效规则重新计算 |

补课沿用**来源日期的周次和单双周**，实际上课时间采用**目标日期的作息**。来源可指定具体日期，也可指定星期以及来源教学周；多个目标选择连续来源日期时，来源按天顺延，预览中逐一列出。独立考试始终按考试本身的日期保留。

同一天不能同时设置多条整日规则，同一来源日期不能重复补课；不支持把另一个补课目标再次作为来源的连锁规则。变更记录可在日历中查看和撤销。

内置 2026 年中国大陆节假日日期标记；其他年份可手动添加。节假日标记不会自动停课，也不会自动套用全国调休日的教学安排，需按学校通知确认。

## 三种导入方式

导入前可指定已有学期，或先新建一个学期再返回导入流程。识别预览及差异比较始终针对所选目标，不把导入内容直接覆盖到当前显示的另一个学期。

### 正方教务网页

「导入课程」显示通用的「正方教务」入口。首次填写自己的完整教务网址，保存后可再次修改；没有预置学校网址。

在独立教务浏览器中自行登录，选择正确学年、学期并进入实际课表，然后点顶部「导入此页」。账号密码无需交给应用作者。支持常见新版正方课表单元格、tooltip 字段和 HTML 表格结构；不同学校的定制页面仍可能需要适配。

校园内网、VPN、验证码和统一认证由学校控制。跨域 iframe、画布绘制、图片课表及特殊页面可能无法读取，可尝试直接进入课表网址，或改用 PDF、粘贴文字和手动录入。内置浏览器暂不提供课表附件下载；PDF 可先通过系统浏览器下载到手机，再从本地导入。

### 本地 PDF

选择「课表 PDF」，通过文件选择器打开文件，识别后核对并确认。PDF.js 及所需资源随应用打包，文件在本机解析，不上传。

- 单文件最多 **20MB、30 页**。
- 支持含可提取文字、星期列和课程字段的课表 PDF；不含 OCR，扫描件、图片型 PDF 暂不支持。
- 无法可靠识别名称、星期、节次或周次时会显示提示，不用默认值猜测课程。完整识别的条目可在预览中修正，缺失安排可手动补录。
- 已有解析样例与自动验证，但尚未拿到用户学校实际导出的 PDF，不能保证所有正方模板均可正确识别。首次使用请逐条核对。

### 粘贴文字、HTML 或 JSON

支持包含课程名、星期、节次和周次的文本、从表格复制的文字、常规课表 HTML 及课程 JSON。学校字段不完整时会给出原因；不会把未知周次扩展成全学期。

### 重新导入与差异保护

导入前显示新增、相同、有变化、来源缺失和需要核对的条目，默认仅勾选新增项。相同安排跳过；变化项需要选择后才更新；来源缺失不会自动删除。

程序保留导入来源快照，用于辨别后续教务变化与手动修改。重新导入时保护手动改过的课程字段以及有关联单次调课的基础时间；课程简称、颜色、考核方式、性质和备注不会被变更导入覆盖。同名但缺少唯一对应依据的课程不会自动合并，可以明确选择新增为独立课程。第一版迁移数据没有导入来源快照，无法唯一判断的变化会要求核对。

## 课前提醒与课程状态通知

两个功能独立开启，默认关闭。课前提醒显示课程名称、地点和开始时间，提前量可选 0–120 分钟，默认 10 分钟。同一堂连堂课默认只在开始前提醒；可另开「课间结束提醒」，在有实际课间的小节继续上课时提醒。

课程状态通知在课前窗口及上课期间显示，自动切换上课／课间／继续上课状态；收起和展开时都显示系统计时器，可选择距课间或下课倒计时，或累计授课时间。课间显示距继续上课的时间，并冻结累计授课时间。没有处于提醒窗口的课程时收起。调课、取消、作息修改、考试编辑和学期切换都会同步更新通知计划。

1. 在「提醒与课程状态」中启用所需功能，并允许系统通知。Android 13 及以上需要通知授权。
2. 检查「课前和课间提醒」「课程状态」两个通知频道。可点「发送测试通知」确认系统是否允许显示。
3. Android 12 及以上可通过「准时提醒权限」进入系统授权页。未允许精确闹钟时会使用可能延迟的系统调度，页面会提示状态。
4. 小米／MIUI／HyperOS 等系统若在退后台或锁屏后限制提醒，请检查应用通知、后台运行、自启动及省电限制设置；菜单名称随系统版本变化。应用不能代替用户开启厂商权限，也不能保证在严格省电限制下准时送达。

Android 14 允许用户划掉多数持续通知，因此状态卡并非不可清除。系统「强行停止」应用后，需要重新打开清课以恢复计划。开机、应用更新及系统时间变化会触发重排，但仍受设备权限与后台策略影响。调度使用手机本地时间，尚无独立校园时区设置。

## 口令分享与跟随更新

分享服务已部署在 [qk.sagiri.org](https://qk.sagiri.org)。从「设置」→「分享与数据」→「分享与跟随」进入，可保留此默认地址，也可填写自行部署服务的 HTTPS 根地址。只有主动确认分享后才上传所选学期；平时查看和编辑本地课表不需要联网。

自行部署的接口、资源限额与代理配置见 [分享服务说明](server/README.md)。

### 创建与导入分享

1. 分享者选择一个学期、有效期及分享范围，先预览，再点「上传并生成口令」。默认是单次副本，有效期可选 1／7／30 天。
2. 在口令页面复制分享消息，或调用手机系统分享。消息包含学期名称、20 位口令、打开链接和 App 下载地址；持有口令的人可以读取这份课表，请只交给需要的人。
3. 对方打开链接，或在「输入口令导入」中粘贴整段消息、链接或口令。核对分享服务，点「读取并预览」，再确认导入为**新学期**；既有学期继续保留。所有实体重新生成本地编号，不与已有课程混用。

默认分享课程、教师、教室、作息、停补课和日期标记。**备注／调课说明、考试安排默认不上传**，只有勾选后才包含；教务网址、账号密码、Cookie、通知偏好及导入来源始终不进入分享内容。后续自动发布沿用创建时确认的备注和考试范围。

### 分享链接与网页入口

分享链接采用 `https://qk.sagiri.org/s#code=<20位口令>&server=<编码后的HTTPS根地址>`。链接保留这份课表实际使用的服务地址；接收时先显示该来源，不会擅自替换为默认服务，也不会改动接收者保存的默认服务设置。

Android 可以通过分享链接进入清课；如果先打开网页，点「打开清课」尝试唤起应用。网页只显示口令和服务域名，不读取课表内容。没有打开时可手动选择下载 APK，或「复制分享消息」后打开 App；页面不会自动下载，也不能可靠判断手机是否已安装清课。微信内可按提示改用系统浏览器打开。实际跳转受浏览器、系统及链接关联设置影响，并非所有浏览器都已验证。

口令放在 URL 的 `#` 片段中，浏览器请求落地页时不会把它发给网站；读取课表发生在 App 中明确确认之后。不要将口令或管理令牌自行改放到链接查询参数中。主页介绍、下载入口和分享落地页位于 [qk.sagiri.org](https://qk.sagiri.org/)。

### 复制消息后打开 App

Android 安装版默认开启「打开 App 时识别清课分享」。复制朋友发来的整段分享消息，再打开清课，应用会在前台于手机本地识别其中格式有效的清课分享链接，先显示口令与服务地址。**识别本身不联网读取，也不自动导入**；核对来源后点「读取并预览」，看过内容并确认后才保存为新学期。

可到「设置」→「分享与数据」→「分享与跟随」→「分享链接与剪贴板识别」关闭。其他剪贴板文字、密码不会保存或上传；学校教务浏览器不参与识别，系统可能显示正常的剪贴板访问提示。

同一份剪贴板消息不会反复提示；复制或转发自己创建的分享，也不会因返回 App 而反复提示导入自己的课表。正在编辑或已有弹窗时，新收到的分享暂缓展示，结束当前编辑后再处理；原有课程和未提交表单不会被分享入口直接覆盖。

### 持续分享与跟随

双方分别选择是否启用：分享者勾选「允许朋友持续跟随更新」，导入者再勾选「跟随分享者的后续更新」。未勾选时只导入当前副本。持续分享可选 7／30／180／365 天，开启已有分享的持续更新会在确认后续期为 180 天；普通更新保留原到期时间。

- 分享者保存本地修改后，前台联网时等待约 **1.5 秒**合并连续保存，再发布这个已授权学期的新版本。其他学期、未保存的编辑草稿和未勾选的私人字段不会随之上传。
- 跟随者在打开应用、回到前台或手动检查时读取更新；应用停留前台时约每 **5 分钟**检查一次。编辑弹窗打开时自动同步暂缓；后台没有轮询服务或实时推送。
- 更新以「上次收到的版本／当前本地版本／分享者新版本」进行三方合并。无冲突变化可自动接收，本地新增课程、考试和个人修改保留；同一字段双方都改动时先显示核对界面。
- 核对时可「合并并保留我的修改」，也可另行确认「使用分享者版本」替换该学期；应用前保留恢复版本。慢网络响应到达时若已经转到其他编辑表单，会保留待核对更新，避免打断编辑。
- 分享者遇到服务器版本冲突时停止自动覆盖，需到分享管理核对后重新发布。跟随者可以暂停或解除跟随，分享者可以关闭持续跟随或撤销口令。

撤销、到期或解除跟随都不会远程删除已经导入的本地副本。离线仍可查看课表，重新联网后再检查。分享管理凭证与跟随状态仅保存在当前设备中；清除数据、卸载和换机前请查看下面的备份范围。

## 备份、恢复与隐私

在「设置」→「分享与数据」→「备份与恢复」中选择「导出全部学期」，保存 JSON 备份，内容包括全部学期、课程、考试、作息、调课、导入来源和应用偏好。恢复兼容第一版备份；校验通过并确认后替换当前全部学期。备份导入、导出大小上限为 5MB。

**普通课表备份不包含分享管理凭证、跟随关系和同步版本记录**。换机后本地课表可以恢复，已有分享不能凭课表备份恢复管理权限，跟随需重新输入口令导入并选择开启。清除应用数据前，可先撤销不再需要的分享；未撤销的分享仍会按原有效期失效。

升级前快照单独保留，编辑、导入、删除和恢复等重要变更前自动保存恢复版本；普通历史最多保留最近 4 份。在「恢复历史版本」中可恢复或导出。历史版本仍在本机，不能替代手机外的备份。

课程保存在应用 WebView 本地存储；通知计划保存在应用私有存储。无广告 SDK 或统计服务。PDF 在本机解析；课程上传仅发生在主动确认分享，或已明确开启持续分享后的授权范围内。本地页面通过受限原生 HTTPS 接口访问选定分享服务，不能任意读取学校登录 Cookie 或向外域执行通用请求。

教务浏览器与本地课表隔离，学校页面没有应用原生桥接。导入读取经清理的课表 DOM 和可访问的同源 iframe，不读取密码输入、Cookie API 或登录请求。学校登录会话由 WebView 保存，Cookie 不进入课表备份。

卸载或清除应用数据会删除课表、恢复历史、分享管理凭证、跟随关系及登录会话，请先导出并妥善保存备份。自行构建或来自其他签名的安装包不能直接覆盖官方版本；请先导出备份，再决定是否迁移，课表备份的范围仍受上述限制。

## 应用更新

在「设置」→「应用」→「检查更新」手动检查官方 GitHub Release，查看版本与更新说明，再选择下载和安装。默认使用第三方 **GHFast** 代理；可保存为「直接连接 GitHub」，或填写自己的 HTTPS 代理根地址。自定义代理不带路径、参数或账号密码，更新来源仍固定为 [SAGIRIxr/qingke](https://github.com/SAGIRIxr/qingke)。

下载显示进度并可取消；安装前核对文件大小、SHA-256、包名、版本及与当前应用一致的签名，拒绝降级和调试包。首次安装更新需要允许清课安装应用，返回后继续，最终仍由系统安装界面要求确认。相同签名覆盖安装保留本地课表与设置；应用内更新不提供静默安装，也不会把课程数据发送到更新服务。

尚无更高版本发布、网络无法连接或代理不可用时，可以稍后重试、切换连接方式，或从 [GitHub Releases](https://github.com/SAGIRIxr/qingke/releases) 下载正式 APK。长期签名配置与构建方法见 [Android 构建说明](README-native.md)。

## 开发与验证

前端测试与预览不需安装 npm 依赖：

```powershell
npm.cmd test
npm.cmd run dev
.\android\test-notifications.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-android.ps1 -Configuration Release -Offline
```

预览地址为 `http://127.0.0.1:4173`。网页预览支持课程编辑、本地 PDF／文本导入和备份下载；教务页面直接捕获与 Android 系统通知需要在 APK 中体验。桌面网页使用浏览器 fetch 测试分享时，服务必须明确允许对应 Origin；部署服务默认不开放任意本地预览来源。测试代理或原生桥接替身仅用于本地验证。

Android 构建使用 Java 21、SDK 35、Gradle 8.11.1 和 AGP 8.7.3，详见 [README-native.md](README-native.md)。先配置自己的私有签名，脚本默认构建 Release，可传入 `-SdkPath`、`-GradlePath`，输出 `dist/qingke-3.2.0-release.apk`。首次下载构建依赖时去掉 `-Offline`；本地调试可显式使用 `-Configuration Debug`。签名私钥不随公开源码提供，自行构建的包不会继承官方签名。

正式包使用固定维护签名并关闭调试。当前不包含桌面小组件、图片 OCR 或应用退出后的云端实时推送。功能说明不代表每个设备和场景都已验收，具体完成项与未验证范围以 [TESTING.md](TESTING.md) 为准；自动化检查不能代替所有学校模板、系统通知策略和实际升级流程的验证。

主要目录：

- `www/`：离线界面、课程／考试／日期引擎、重叠安排核对、导入解析、分享入口、跟随合并、月历、课程进度、触控动画及 PDF.js 本地资源。
- `android/`：Android 外壳、独立教务浏览器、文件选择器、通知调度、受控分享链接与剪贴板识别、受限分享 HTTPS 接口及签名校验更新。
- `server/`：官网与分享落地页、分享 API、字段白名单、版本并发保护、SQLite 存储及部署配置。
- `tests/`：日期规则、迁移、备份、导入差异、分享合并、异步编辑保护和动画验证。
- `scripts/`：开发预览与构建脚本。
- 本地截图、设备检查记录、升级前备份及工作过程文档不包含在公开源码中。

详细检查记录见 [TESTING.md](TESTING.md)。
