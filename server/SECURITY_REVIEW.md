# 官网与分享后端安全复审

日期：2026-10-02。范围：官网静态页面、分享 API、数据校验、Gunicorn 与专用 systemd 服务部署；对照实际运行配置，并执行有限合成测试。本轮未测试手机、未读取真实课表、未扫描其他站点，未做公网压力或慢连接攻击测试。这是限定范围的审查，不能作为“没有任何漏洞”的保证。

## 已修复并部署

| 项目 | 风险与证据 | 处理结果 |
| --- | --- | --- |
| 恶意课表造成接收端资源放大（中等） | 小于 1 MiB 的数据也能包含大量同日重叠安排，客户端全学期冲突列表会平方增长。本机小样本确认增长趋势，没有在手机或公网执行大样本。 | 分享创建、更新增加展开预算；读取既有分享也检查预算。最多 10,000 次候选安排、单日 128 次实际安排、全学期 200,000 个保守同日冲突引用。预算计算包含停补课、单次调课和考试，不构造冲突图。 |
| 无效请求耗尽小时创建配额（中等，部分缓解） | 原流程在 JSON 校验前计入创建额度，少量无效请求即可用完该额度；真实代理目前还共用来源桶。 | 无效数据仍消耗请求级额度，只有规范化成功才消耗创建额度。共享来源桶问题仍在，见下文。 |
| Python 与 JavaScript 校验不一致（低） | 部分非 ASCII 时间数字、含大量非 BMP 字符的字符串会被后端接纳，却无法通过 App 校验。 | 日期／时间仅允许 ASCII 数字，文字长度与 JavaScript UTF-16 单元计数一致，无效代理码点提前拒绝。 |
| 传输与代理修改防护（加固） | 原公网缺少 HSTS；CDN 仍可能给 HTML 注入统计脚本。 | 静态与 API 返回当前主机 HSTS；不加入 includeSubDomains 或 preload。静态响应加 no-transform，继续保留严格 CSP。公网效果见验证记录。 |
| 官网与 App 的端口边界不一致（兼容修复） | 网站允许 HTTPS 端口 0，App 拒绝。未发现目的地逃逸或注入。 | 官网同步拒绝端口 0，含归一化后的 00000。 |

预算检查不删除旧分享，也不改写其内容。旧分享过于密集时返回明确错误，撤销接口仍可使用；现有 App 的手动更新先读取分享，因此应撤销旧分享、精简后重新分享。已持有有效管理令牌及版本号的 API 调用仍可直接更新。普通个人课表不需要改变格式。

## 已确认有效的防护

- SQL 数据参数化；随机读取口令与管理令牌分离，数据库保存凭证哈希，修改与撤销校验管理令牌，版本更新使用事务和 CAS。
- 1 MiB 正文上限；拒绝重复 JSON 键、非法 UTF-8、非有限常量、异常深度、未知字段和无效引用。错误响应及应用日志不输出课表、口令、令牌或内部异常文本。
- 分享页将外来文本写入文本节点；路由采用固定文件映射，未发现可复现的 XSS、开放重定向、路径遍历或目录读取。页面不请求课表 API，链接口令位于 fragment。
- 实际服务使用独立非 root 用户，仅监听 loopback。应用文件由 root 持有且不可由服务用户修改，数据目录 0700、数据库 0600；NoNewPrivileges、只读系统目录、私有临时目录、内存及进程上限已生效。
- 公网 HTTP 返回 301 跳转 HTTPS。CSP、no-referrer、nosniff 和禁止嵌入策略已核对。

## 尚需处理或确认的边界

1. **真实来源 IP 与共享限流。** 当前 QINGKE_TRUST_PROXY=false，用户共用反代的 loopback 配额。一个用户仍可能占用其他人的额度。本轮没有可靠核实 Lucky 覆盖来源头以及 CDN 到源站的完整信任链，因此没有直接启用代理信任，也没有修改 Lucky、Cloudflare 或防火墙。应确保来源头由可信代理覆盖，确认直接访问源站无法伪造该头，再启用按真实来源限流；全局配额仍须保留。
2. **慢正文保护待核实。** gthread 的 worker timeout 不等于单请求正文读取截止。需要在 Lucky／入口代理落实读取截止和向上游发送前的正文缓冲，避免少量未完成请求长期占用线程；本轮没有进行线上慢请求试验。不能用后台线程加等待超时来冒充已经取消阻塞读取。[Gunicorn 超时说明](https://gunicorn.org/reference/settings/#timeout)
3. **上游补丁的发布渠道差异。** 生产仍使用锁定哈希的 Gunicorn 26.2.0。核对时官方 GitHub 已发布 26.2.2，26.2.1 的说明含 HTTP/1 分块解析边界修复；但实时 PyPI 元数据仍以 26.2.0 为最新，26.2.1／26.2.2 包接口返回 404。本轮没有用未经独立构建验证的源码包替换线上依赖。后续应取得可验证的补丁产物、在隔离环境回归后升级；不能据此声称上游解析风险已全部解决。[26.2.1 说明](https://github.com/benoitc/gunicorn/releases/tag/26.2.1)、[26.2.2 说明](https://github.com/benoitc/gunicorn/releases/tag/26.2.2)、[PyPI 元数据](https://pypi.org/pypi/gunicorn/json)
4. **CDN 遥测单独管理。** CSP 拦截统计脚本不代表 NEL 网络错误上报已关闭。NEL / Report-To 由 CDN 注入，且 NEL 开关是 zone 级；关闭前应考虑其他子域。不要为通过统计脚本而放宽 CSP。[Cloudflare Web Analytics](https://developers.cloudflare.com/web-analytics/get-started/)、[NEL 说明](https://developers.cloudflare.com/network-error-logging/)
5. **客户端连接其他服务仍需防御。** 本轮预算保护适用于本后端；自建或恶意分享服务仍可向旧客户端返回高复杂度数据。客户端导入／跟随入口预算和通知生成不构造无用冲突列表，应作为后续客户端加固处理。本轮没有更改 App，也没有宣称客户端自身的平方复杂度已修复。
6. **分享内容与下载来源的信任边界。** 分享是持口令可读，服务器能读取明文课表，不是端到端加密。第三方下载代理仍是首次安装的信任对象，官网保留 GitHub 直连并明确标注代理；没有发现其篡改安装包的证据。

## 验证记录

- 本机及服务器隔离临时数据库：45 项 Python 测试通过；新增 18 项字符／展开预算测试、2 项创建配额与旧分享读取回归。
- Node 回归共 152 项通过，其中网站链接 6 项，包括端口 0 与 App 一致性。
- 20 组有限合成安排与客户端引擎的按日展开结果逐项一致。
- 公网唯一新建的虚构分享：创建 201 → 读取 200 → 错误令牌撤销 404 → 正确撤销 204 → 撤销后读取 404。没有重试创建，测试分享已清理。
- 公网首页、分享页和健康检查均返回 200，HSTS 已生效；静态页面返回 no-store, no-transform，HTML 中的 Cloudflare 统计脚本注入已消失。NEL / Report-To 响应头仍存在，未将其误报为已经关闭。
- 部署仅替换三个应用文件，备份旧文件并保留回滚路径，重启专用分享服务；分享数据库、环境、用户反代与其他服务未修改。
